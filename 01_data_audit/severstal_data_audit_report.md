## 1. 比赛背景

### 1.1 主办方与业务背景

本比赛是 **Severstal: Steel Defect Detection**，由俄罗斯钢铁与矿业公司 **Severstal（谢韦尔钢铁）** 于 2019 年在 Kaggle 举办（2019-07-26 开赛，赛期约 3 个月，总奖金约 12 万美元，冠军 4 万美元）。

Severstal 在生产线上用高频工业相机拍摄钢板表面，希望用计算机视觉自动发现表面缺陷，替代人工质检：检测不及时的缺陷流入下游会给客户带来安全风险，也会损害企业声誉。比赛要求参赛者**对钢板表面缺陷进行像素级定位与分类**，属于典型的工业视觉语义分割任务。

### 1.2 比赛任务

给定一张钢板表面图像，输出 4 个类别各自的**像素级缺陷掩码**（可以多类别共存，也可以无缺陷）：

- 图像尺寸：宽 1600 × 高 256；
- 类别数：4（`ClassId = 1, 2, 3, 4`）；
- 训练集：12,568 张；测试集：5,506 张；
- 输出形式：按"图片 ID + 类别"提交 RLE 掩码；无缺陷的类别提交 `-1`。

### 1.3 评估指标

官方指标为 **Dice 系数（平均）**：

```
Dice = 2 × |X ∩ Y| / (|X| + |Y|)
```

其中 X 为预测像素集合，Y 为真实像素集合；当 X 与 Y 都为空时，Dice 定义为 1。最终得分为**测试集上所有 <ImageId, ClassId> 组合的 Dice 均值**（共 5506 × 4 个组合），因此"把无缺陷类别判为空掩码、把有缺陷类别判准"同样重要。

### 1.4 提交格式

官方提交文件格式为两列：

| 列名 | 说明 |
| --- | --- |
| `ImageId_ClassId` | 如 `0000f269f.jpg_1`，每张测试图 4 行（对应 4 个类别） |
| `EncodedPixels` | 该类别的 RLE 掩码；无缺陷填 `-1` |

官方提交文件应有 **22,024 行**（5,506 张 × 4 类）。详细格式见第 2.6 节。

### 2.2 train.csv 字段

| 列名 | 类型 | 说明 |
| --- | --- | --- |
| `ImageId` | str | 图片文件名，如 `0002cc93b.jpg` |
| `ClassId` | int | 缺陷类别，取值 1–4 |
| `EncodedPixels` | str | RLE 编码的掩码；本文件中没有 `-1` 行 |

一个（`ImageId`, `ClassId`）对应一行；同一张图可出现在多行（多类别），同一类别在一张图上的多个不连续缺陷区域会被合并进同一条 RLE。

### 2.3 缺陷类别定义（标签体系）

Kaggle 官方数据仅给出匿名数字类别 `ClassId = 1, 2, 3, 4`，没有公布四类对应的正式缺陷名称。因此本项目统一使用 `class_1`～`class_4`，不把样例图的视觉形态当作官方语义。

| ClassId | 项目名称 | 官方语义名称 |
| --- | --- | --- |
| 1 | `class_1` | 未公布 |
| 2 | `class_2` | 未公布 |
| 3 | `class_3` | 未公布 |
| 4 | `class_4` | 未公布 |

### 2.4 RLE 掩码编码规则

- 掩码为 1600 × 256 = **409,600 个像素**的一维展平数组；
- 像素编号按"先列后行"（列优先）排列：像素 1 = (x=0, y=0)，像素 2 = (x=0, y=1)，…，即 `index = x × 256 + y + 1`；
- `EncodedPixels` 是一串空格分隔的**整数对**：`起始像素(1-based) 长度 起始像素 长度 ...`；
- 例如 `1 3 10 5` 表示像素 1、2、3 和 10–14 属于掩码；
- 解码时先把数组 reshape 为 (1600, 256)，再转置得到 (256, 1600) 的图像掩码。

示例（`0002cc93b.jpg`，类别 1）：

```
29102 12 29346 24 29602 24 29858 24 ...
```

### 2.5 无缺陷样本的表示（重要）

**本数据集的无缺陷图片不在 train.csv 中。** train.csv 只包含 6,666 张"至少有一种缺陷"的图片的 7,095 条标注；另外 **5,902 张训练图片在图片文件夹中但没有任何标注行，它们就是无缺陷样本**（约占总训练图片的 47%）。训练时需要把这些图片以"全零掩码"的形式纳入，否则模型学不会输出空掩码。

### 2.6 本地 sample_submission 与官方格式的差异

本地的 `sample_submission.csv` 是**简化占位版**：

| 列名 | 内容 |
| --- | --- |
| `ImageId` | 测试图片 ID，共 5,506 行（每张图仅 1 行） |
| `EncodedPixels` | 全部为 `1 409600`（全图掩码占位） |
| `ClassId` | 全部为 `0`（占位值） |

官方要求的格式是 `ImageId_ClassId` + `EncodedPixels`（每张图 4 行、共 22,024 行）。**最终提交前必须转换为官方格式**，无缺陷类别填 `-1`，否则会提交失败或得分错误。

## 4. 关键发现与建模建议

1. **数据质量干净**：无缺失、无重复行、无非法标签、无损坏图片，可放心直接使用。
2. **类别严重不均衡**：`class_3` 占标注行数的 72.6%，`class_2` 仅 3.5%。建议使用类别加权损失（如 Weighted BCE/Dice/Focal）、类别重采样或 TTA，并单独关注 `class_2` 的召回。
3. **无缺陷样本不在 CSV 中**：5,902 张无标注图片（47%）就是无缺陷样本，建议在训练数据中补全零掩码标签，否则模型偏向"永远输出掩码"，提交时还要另做空掩码阈值。
4. **多标签共存**：427 张图含多类别缺陷（425 张双类别 + 2 张三类别），输出层应做多类别独立预测（4 个通道），而不是互斥的单标签分类。
5. **提交格式转换**：本地 sample_submission 是简化占位版；最终提交需生成 `ImageId_ClassId`（22,024 行）格式，无缺陷类别填 `-1`。
6. **掩码面积差异大**：`class_1`、`class_2` 掩码较小（中位数约 3,000 像素），`class_3`、`class_4` 较大（中位数约 1 万～2.5 万像素），建议按类别设置面积阈值做后处理，过滤小噪声区域。
7. **使用冻结划分**：覆盖全部 12,568 张图片且已消除已识别近重复泄漏的最终 v2 划分见 `split_report.md`，建模时统一读取该版本。
8. **图像按灰度处理**：所有图片是等效灰度图，可读为 1 通道（或 3 通道灰度输入）以省显存。

## 5. 结论

本地数据集包含 12,568 张训练图、5,506 张测试图、7,095 条正缺陷标注和 4 个匿名数字类别。`train.csv` 无缺失、无重复、无异常 ClassId，严格 RLE 校验全部通过，图片文件数量完整。需要特别处理的有四点：无缺陷图片不在标注 CSV 中（需补全零掩码）、类别极不均衡（`class_3` 主导）、提交前需核对并转换为比赛要求的格式，以及建模时必须使用最终冻结的 v2 划分避免已识别的近重复泄漏。
